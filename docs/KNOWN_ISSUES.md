# 既知の不具合・制約

コード監査に基づく正直な一覧です。重大なクラッシュや再現するバグは今回の監査では見つかっていませんが、下記は「仕様との差異」「一部実装」「未検証」「設計上の制約」です。

## 仕様との差異・一部実装

| 項目 | 内容 |
|---|---|
| Paint の配置 | 色スウォッチは仕様の右パネルではなくツールパレット(既定は上部リボン、設定で左側)にある。ツールバーに切り取り/コピー/貼り付けボタンはない(Edit メニューのみ) |
| AI 編集(v0.1.0) | **保留**: 消しゴムマジック(物体除去)は macOS に公開 API が無いため未実装。AI アップスケールは VideoToolbox の超解像(VTSuperResolutionScaler / LowLatency)を検証したが、画像用は 4 倍・1920px 以下限定かつ本機では出力が空、低遅延版は YUV 4:2:0 動画専用かつ 2 倍で 960px 以下のため見送り(通常の拡大は イメージ > 画像のサイズ変更)。背景削除・被写体コピーは選択範囲を無視して画像全体の被写体を使う |
| スライドショーの表示 | 実行中はツールバー/ステータスバーを隠す。メニューバーの自動非表示はフルスクリーンに入るときにだけ指定できるため、既にフルスクリーンの状態で開始した場合はシステム設定どおりになる |
| Photo のレイアウト | ファイル名はツールバーではなくタイトルバー。n/m 表示は画像が複数のときのみ(ウィンドウのサブタイトルにもあり)。独立した Paint ボタンはなくセグメントコントロール |
| ズームスライダー | **実装済み**: ステータスバーに対数スライダー(10%〜3200%、表示中心でズーム)とクリックで編集できる%欄(Enter 適用・Esc 取消)。ウィンドウ幅が約560pt未満だとスライダーは隠れる。操作後はキャンバスにフォーカスを戻す。実機でのマウス操作は未確認(ロジックはユニットテスト) |
| 新規キャンバス | **実装済み**: ⌘N / ツールバー「New」でダイアログ(幅・高さ・プリセット・背景 白/背景色/透明/カスタム)。起動時・Dock 再オープンで自動作成される無題キャンバスはダイアログなしで既定値(設定 > Paint)で開く。ダイアログ表示そのものは実機未確認(シームでユニットテスト)。キャンバスサイズシートに縦横比固定はない(リサイズシートにはある) |
| 図形「多角形」 | ドラッグ範囲に内接する正 N 角形。クリックで頂点を打つ任意多角形ではない |
| 図形「曲線」 | フリーハンドを Catmull-Rom で平滑化。制御点つきベジェではない |
| 図形の再編集 | 確定後は不可(ラスター化される) |
| 自由選択 | ドラッグで描く投げ縄。クリック式の多角形投げ縄ではない |
| テキスト | オプションは枠全体に適用(範囲選択ごとではない)。色は前景色で不透明度を無視。確定後はラスターで再編集不可。クリックで枠外を押すと確定。プレーンテキストのクリップボードからテキストボックスを作る経路はない |
| ドラッグ&ドロップ | Paint の「挿入」は **最初の1ファイルのみ**(複数は「新規画像として開く」)。標準カーソル以外のドロップ強調表示なし |
| クリップボード | ペーストボードの最初の画像のみ使用。Photo モードでは貼り付け不可(「新規画像として貼り付け」は可) |
| 印刷 | 常にフィット(印刷領域に中央・縦横比維持)。独自の拡大率オプションなし。システムパネルの拡大率が反映されるかは未確認 |
| 保存失敗 | システムのエラー文言のみ。ディスクフル専用の表示・テストなし |
| ウィンドウ/タブ復元 | AppKit の自動タブ・NSDocument 復元と `NSQuitAlwaysKeepsWindows` に依存。テストなし |
| 性能プリセット | プリセット選択後に個別値を変えても「カスタム」に切り替わらない |
| 極端なケース | 150MP 超・極端な縦横比のテストなし。0バイトや権限なしの個別テストなし |

## 設計上の制約(文書化済み)

- **8bit 編集**: キャンバスは 8bit RGBA プリマルチプライド。16bit・浮動小数の画像は 8bit に変換される。
- **150 メガピクセルの編集上限**(`ImageLoader.maxEditablePixels`)。超える画像は `tooLarge` エラーで編集不可。閲覧はダウンサンプルしたプレビューで可能。
- **アニメーション画像は最初のフレームのみ編集**。保存してもアニメーションは保持されない(Paint 移行時に警告)。
- **領域アンドゥのメモリ**: 128×128 タイル単位。密なストロークはバウンディングボックス全体を保持し、バイト上限がない(最悪ケース: 6000×4000 で 50 段 × 96MB)。段数(5〜200)でのみ制限。大きな編集はメイン外で実行される。
- 6000×4000 のキャンバスは 192MB(レイヤー+合成)+追加レイヤーごとに 96MB。150MP は約 1.2GB。
- キャッシュは NSCache(厳密な LRU ではない)。キャンセルは待機中の先読みのみで、実行中のデコードは止まらない。`ImageCache.remove(url)` は固定の6つのサイズクラスのみ破棄。
- 消しゴムの不透明度は 1 固定。ブラシは AA 設定に関わらず常に AA。ソフトブラシの硬さは固定(スライダーは丸ブラシのみ)。
- ブレンドモードなし。キー再割り当てなし(ショートカット一覧は読み取り専用)。
- 切り取りは背景レイヤーでも透明ピクセルを残す。投げ縄での切り抜きは外接矩形になり、パス外の画素も残る。
- v0.1.0 から App Sandbox は無効(Developer ID 配布)。デスクトップ・書類・ダウンロード・ネットワーク/外部ドライブは初回アクセス時に macOS が場所ごとに一度確認する(フルディスクアクセスを許可すれば出ない)。確認を拒否した場所では開いた1枚のみ閲覧でき、「フォルダへのアクセスを許可…」で個別に許可できる。
- 言語切替は再起動後に反映。
- Photo モードのドラッグは、画像が収まっているときはドラッグアウト、収まらないときはパン。
- 共有ボタンは Photo ツールバーの既定セットにのみある(Paint では追加可能な項目)。
- スライドショーは Photo モードのみで、未保存の編集があると開始不可。
- 開発ビルドの署名は ad-hoc(`CODE_SIGN_IDENTITY "-"`)。配布用 DMG(GitHub Releases)は Developer ID で署名している。
- ビルド: 同じ derivedData での並列ビルドは `database is locked` で失敗しうる。
- コード: `MainWindowController.swift` は 733 行+拡張 10 ファイルで、変更の集中点(ホットスポット)。

## 評価に関する注意

- 性能数値は Debug 構成・テストホスト内の画面外計測で、Release や実 GUI の計測はない。起動時間はプロセス内計測のみ(約 130ms)。
- 初期ズームが「ウィンドウにフィット」であることを直接アサートするテストは見つかっていない(実機では Photo ウィンドウで確認)。
- 複数ファイルを開く際、その中の1つが他のウィンドウで既に開かれていると、既存ウィンドウのセッションが新しい一覧に置き換わる(意図的な動作だがテストなし)。
- `.dpp` の壊れた/新しいバージョンのパッケージを開くテスト、BMP/TIFF/HEIC の保存往復テスト、埋め込みプロファイル保持の直接テストはない。
- 外部変更の自動再読込と削除バナーの UI は通しでテストされていない。
- リポジトリは git 管理されていない。
